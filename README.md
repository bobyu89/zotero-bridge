# ZotMax

給 Zotero 10 的研究生文獻外掛：把你在 Zotero 收的文獻、PDF 劃線、筆記和評讀，整理成 **Obsidian 筆記**或 **Notion 資料庫**；要的話，也可以請 AI（自備 Claude 或 OpenAI 的 API key）先替每篇寫一份結構化的研讀筆記。

**給誰用**：台灣的護理研究生。在 Zotero 收文獻、在 Obsidian 或 Notion 做筆記，要交課堂報告、做系統性／範圍回顧、寫實證健康照護（EBHC）報告或論文第二章文獻探討的人。

**整理、追蹤、評讀交給它；找文獻和寫作留給你。** 新安裝預設是「研究生引導」模式：自動找文獻和 AI 寫草稿的功能先關著，每個功能都能單獨開關。

- **下載**：[最新版 `.xpi`](https://github.com/bobyu89/zotero-bridge/releases/latest)。裝一次之後，Zotero 會自動檢查並更新。
- **[安裝精靈](https://bobyu89.github.io/zotero-bridge/)**：依你的電腦、AI 服務商和筆記工具調整步驟，一步一步打勾完成，進度會記住。
- **[醫學文獻快速搜尋](https://bobyu89.github.io/zotero-bridge/search.html)**：PubMed、CINAHL、Cochrane、華藝、臺灣博碩士論文一次開，含 PICO 檢索式產生器。不用安裝，手機也能用。
- **[文獻評讀表](https://bobyu89.github.io/zotero-bridge/appraisal.html)**：CASP、JBI 逐題評讀，複製成 Word 或 Markdown 表格。不用安裝。

需要 Zotero 10；Obsidian 建議 1.14 以上（彩色劃線與 Bases 看板）。

## 5 分鐘開始

1. **安裝**：下載 `zotero-bridge-x.y.z.xpi`（用 Firefox 下載請在連結上按右鍵 →「另存連結」，不然 Firefox 會把它當成自己的擴充功能），然後 Zotero → 工具 → 插件 → 右上角齒輪 → **Install Plugin From File…**。
2. **接上筆記工具**（至少一個）：Zotero → 設定 → **ZotMax** →「同步」分頁。
   - **Obsidian**：「Vault 資料夾路徑」選 vault 的根目錄。筆記預設放在 `Zotero/` 子資料夾。
   - **Notion**：建立一個 integration，把資料庫分享給它，貼上 token 和「預設資料庫連結」，按 **測試連線並補齊資料庫欄位**，欄位會自動建好。
3. **AI（選用）**：在「AI 服務」選 Anthropic（Claude）或 OpenAI，貼上 API key。API 另外計費，ChatGPT／Claude 的訂閱方案不能用在這裡。先不想用 AI，就到「功能」關掉「AI 文獻筆記」，或同步時選「同步但不呼叫 AI」。
4. **第一次同步**：在文獻清單選幾篇文獻，按文獻清單上方工具列（「新增筆記」右邊）的 **ZotMax** 按鈕 → **同步所選文獻（Notion + Obsidian）**。
5. **看結果**：Obsidian 的 `Zotero/` 裡每篇一份文獻筆記，最上面是「重點」；Notion 資料庫每篇一頁，欄位可以排序、篩選。

Notion integration 怎麼建、API key 去哪裡拿，[安裝精靈](https://bobyu89.github.io/zotero-bridge/)有逐步說明。以下是設定頁的細節，需要時再展開。

<summary><b>Notion</b>：建立 integration，以及外掛自動建立的欄位</summary>

1. 到 <https://www.notion.so/profile/integrations> 建立一個 **Internal integration**，複製 token（`ntn_` 開頭）。

3. 複製資料庫連結（`https://www.notion.so/...`），貼到「預設資料庫連結」或分流規則。
4. 按 **測試連線並補齊資料庫欄位**。新資料庫用中文欄位（括號裡是舊版的英文名稱）：

| 類別 | 欄位 |
|---|---|
| 書目資料 | 標題（沿用資料庫原本的標題欄）、`作者`（Authors）、`年份`（Year）、`出版日期`（Date）、`期刊`（Publication）、`卷`（Volume）、`期`（Issue）、`頁碼`（Pages）、`出版者`（Publisher）、`文獻類型`（Item Type）、`DOI`、`網址`（URL）、`摘要`（Abstract） |
| 整理用 | `閱讀狀態`（Status；單選：待讀／閱讀中／已讀／已引用／已刪除）、`標籤`（Tags）、`分類`（Collections）、`文獻庫`（Library）、`引用鍵`（Citation Key）、`APA 7`（APA）、`一句話摘要`（Summary）、`全文狀態`（Full Text） |
| 研讀欄位（AI） | `研究設計`（Study Design；RCT、quasi-experimental、cohort、case-control、cross-sectional、qualitative、mixed methods、systematic review、meta-analysis、scoping review、guideline、other）、`樣本數`（Sample Size）、`證據等級`（Evidence Level；Oxford CEBM 2011，1–5）、`JBI 證據等級`（JBI Level）、`評讀工具`（Appraisal Tool）、`評讀結果`（Appraisal；納入／排除／需更多資訊）、`評讀已核對`（Appraisal Verified）、`P 族群`、`I 介入措施`、`C 對照`、`O 結果指標`、`研究場域`（Setting）、`測量工具`（Measures，多選）、`國家`（Country） |
| 連結與同步 | `Zotero 連結`（Zotero）、`Obsidian 連結`（Obsidian）、`Zotero 識別碼`（Zotero Key）、`加入日期`（Date Added）、`最後同步`（Last Synced） |

- **欄位可以改名，但不要刪除或改類型**：外掛記得每個欄位的 ID，改名後照樣找得到，中英文名稱也都認得。你可以自由加自己的欄位（例如「評分」），外掛不會動。
- **舊的英文欄位照常運作**：再按一次「測試連線並補齊資料庫欄位」會用原本的語言補上缺的欄位。想改成中文，按 **把 Notion 欄位改成中文…**：先列出每個要改的欄位（例如 `Authors → 作者`），確認後才依欄位 ID 改名，資料不動。已有同名中文欄位的不會改。Notion 公式、篩選或其他整合用到這些名稱的，要自己跟著改。
- DOI、APA、JBI、PICO 的 P／I／C／O 這類慣用英文的詞保留英文。
- 舊的 AI 筆記沒有結構化資料時，研讀欄位維持原值，不會被清空。
- 文獻比較表、PRISMA、進度報告要建成 Notion 頁面時，另外填「文獻比較表的 Notion 父頁面」（也要分享給 integration）。

<summary><b>Obsidian</b>：子資料夾、檔名、Bases 總表與 frontmatter</summary>

- **預設子資料夾**：例如 `Zotero`。
- **檔名格式**：建議用 Citation key（沒有時用「作者 年份 - 標題」）。Zotero 10 有內建 Citation Key 欄位；有裝 Better BibTeX 也會讀取。
- **建立「Zotero 文獻庫.base」總表**（預設開啟）：只建立一次，之後不覆寫你的修改。想要新版的欄位就刪掉舊檔，下次同步重建。
  - 「文獻總表」：標題、作者、年份、期刊、研究設計、樣本數、證據等級、閱讀狀態、分類。
  - 「閱讀進度」：依 `status` 分成待讀／閱讀中／已讀／已引用的看板，拖曳卡片就改了 `status`，下次同步 Zotero 與 Notion 也跟著改。
- **由外掛管理的 frontmatter**：`study_design`、`sample_size`、`evidence_level`、`jbi_level`、`appraisal_tool`、`appraisal_overall`、`appraisal_verified`、`setting`、`population`、`intervention`、`comparison`、`outcomes`、`measures`、`country`、`full_text`、`fulltext`。有新資料時會覆寫，請不要用這些名稱存自己的資料。你自己加的其他欄位（例如 `aliases`）會保留。
- **一併同步 Zotero 子筆記**（預設開啟）。
- **Graph view**：AI 筆記的 `[[關鍵概念]]` 會把談同一件事的文獻串起來；有了概念卡片，每個概念都是真正的節點。

## 兩種模式與功能開關

設定 → ZotMax 的第一個分頁是「功能」。先選一個起點，再逐項調整：

- **研究生引導**（新安裝預設）：找文獻與寫作留給你自己。自動找新文獻、引文追蹤和 AI 寫的草稿先關著，整理、評讀和搜尋連結照常幫你。
- **進階**：全部打開，包括 AI 草稿、批次 API 和自動追蹤新文獻。
- **自訂**：改了任何一個開關、跟兩種模式都不完全一樣時，自動顯示。

開關馬上生效，不用重新啟動。關掉的功能，選單（右鍵、工具列按鈕、快速指令裡標成關閉）、右側面板的列、背景工作和設定頁裡的相關設定都會一起收起來，也不會連網或呼叫 AI。切換模式後可以按「復原」回到切換前。

**設定在哪裡**：設定頁依研究流程分成六個分頁，**功能** · **同步**（Obsidian、Notion、分流規則、自動同步、閱讀狀態、中文 APA、參考文獻檔）· **整理**（全文筆記、劃線顏色、概念卡片、文獻自動分類）· **找文獻**（醫學文獻快速搜尋、NCBI、PubMed 追蹤、引文追蹤）· **篩選與評讀** · **AI**（AI 服務、本月 AI 用量），下次打開會回到上次的分頁。不確定在哪一頁，就在最上面的「找設定」輸入關鍵字，中英文都可以（例如 `Notion`、`API key`、`分類`）：所有分頁裡符合的區塊會一起列出，按 Esc 回到分頁；關著的功能也會列出，按一下就跳到它在「功能」的開關。Zotero 設定視窗上方的搜尋框也找得到這些設定。

<summary>從舊版升級時，開關怎麼設定</summary>

- **第一次有開關的版本**：如果你已經用過外掛（設定了 vault、Notion 資料庫、分流規則、PubMed 追蹤，或有 AI 用量紀錄），新的開關全部打開，原本的行為不變；原本就有的設定（AI 文獻筆記、批次 API、閱讀狀態、中文 APA、圖片劃線）維持你的選擇，所以模式可能顯示「自訂」。全新安裝則是研究生引導。

- 這兩個檢查都只做一次。

## 依研究流程的功能導覽

**入口**：所有功能都在同一份清單裡，三個地方看到的分組和名稱都一樣：

- 文獻清單上方工具列的 **ZotMax** 按鈕（橋形圖示，在「新增筆記」右邊）：第一項是「快速指令…」，接著依流程分成 同步／整理／找文獻／篩選與評讀／AI 輔助與寫作，最下面是「設定…」。作用在你選取的文獻；找重複、PRISMA、評讀總表、引文追蹤納入研究、匯出此分類的參考文獻這類作用在左側選取的分類。
- 條目或分類按右鍵 → **ZotMax ▸**：只有一個子選單，裡面同樣依流程分組，只列出能用在所選文獻（或這個分類）的功能。
- **快速指令**：按 `Ctrl+Shift+P`（macOS：`⇧⌘P`），打字找功能（見下面）。

- **側邊面板**：選一篇文獻（或在 PDF 閱讀器裡），右側的 **ZotMax** 面板就是這一篇的重點、劃線、狀態和常用動作（見下面）。

Zotero 的「工具」選單只留「ZotMax 設定…」、「ZotMax 快速指令…」，以及同步或 AI 批次進行中才出現的停止／繼續／放棄、檢查／取消。

### 側邊面板

選一篇文獻，Zotero 右側面板的右緣有一排直立的圖示，橋形的那個就是 **ZotMax**；在 PDF 閱讀器裡，右邊的側欄也有同一個圖示，顯示這份 PDF 所屬的文獻。面板分成五段，都可以折起來，外掛會記住你開了哪幾段（預設開「重點」和「動作」）：

| 段落 | 內容 |
|---|---|
| 重點 | 和文獻筆記最上面的「重點」同一份資料：一句話摘要；研究設計 · 樣本數 · 證據等級 · 評讀結果；2–3 點主要發現。下面是「在 Obsidian 開啟筆記」「開啟全文筆記」「在 Notion 開啟」（有才出現），以及折起來的完整 AI 筆記。還沒有 AI 筆記時說明怎麼產生（「AI 文獻筆記」關著時告訴你去哪裡打開） |
| 統計解釋 | 「讀懂統計」開著、這篇有解釋過的 PDF 選取時才出現（緊接在「重點」下面）：選的原文、這是什麼／這段在說什麼／臨床上代表什麼／要注意的地方、存到筆記、再解釋得簡單一點；見[讀懂統計](#讀懂統計) |
| 我的劃線 | 依顏色的意義分組，每組的數量與前三則；點一則就在 PDF 打開那個位置 |
| 狀態 | 閱讀狀態、篩選、文獻評讀表（開啟評讀表、對照 AI）、這篇在哪些「自動分類」子分類、上次同步時間 |
| 動作 | 同步、同步但不呼叫 AI、重新產生 AI 筆記、文獻自動分類、搜尋資料庫、引文追蹤、對照 AI（評讀陪練）、快速指令，和工具列按鈕是同一份功能清單，只作用在這一篇；關掉的功能不會出現 |
| 延伸搜尋 | 搜尋連結與 PICO 檢索連結 |

- 面板會跟著變：改了劃線、標籤、筆記、分類，同步或執行完一個動作，或在設定裡開關功能，內容馬上更新。
- 面板標題列右邊的「⋯」可以開快速指令或 ZotMax 設定。不需要時按標題列把整個面板收起來，Zotero 會記住。
- 一次選很多篇時，Zotero 會改顯示多篇文獻的畫面，沒有個別文獻的面板。

### 快速指令

不知道某個功能在哪裡？按 `Ctrl+Shift+P`（macOS：`⇧⌘P`），或工具列按鈕的第一項、工具 → **ZotMax 快速指令…**，輸入功能名稱：中文、英文都可以，大小寫、全形半形不拘，打錯一兩個字母也找得到（例如「分類」、「PRISMA」、「流程圖」、「評讀」、「CASP」、「sync」）。上下鍵選擇、Enter 執行、Esc 關閉；執行時用的是你當下在 Zotero 選取的文獻或分類。

- 每個結果旁邊標出它在哪一組。現在不能用的會說原因：功能關著時寫「到 設定 → 功能 打開『…』」，按 Enter 或「打開設定」直接到那個開關（關著的功能找得到，但不會執行）；需要選取時寫「先選取文獻」或「先選取分類」。
- 也能找設定頁的區段，例如「設定：Notion」、「設定：文獻自動分類」，Enter 直接打開那一段。
- 快速指令一直都在，關掉「工具列按鈕」只是收起按鈕。快捷鍵只在主視窗的文獻庫畫面有效；如果你把 Zotero 自己的快捷鍵改成用 P，外掛就不佔用它。

### 收集與同步

**同步**把每篇文獻的書目、摘要、PDF 劃線（含頁碼連結）、你的 Zotero 子筆記、評讀和 AI 筆記，寫成 Obsidian 的一份筆記和 Notion 的一頁。APA 7 引文由 Zotero 內建的 CSL 引文處理器產生，不讓 AI 編參考文獻。Notion 頁面有開 Obsidian 的連結，Obsidian 筆記有開 Notion 和 Zotero 的連結，每條劃線都能點回 PDF 原位置。

**重新同步不會蓋掉你寫的東西。** Obsidian 只改寫 `%% zotero-bridge:start %%` 到 `%% zotero-bridge:end %%` 之間，區塊外的文字、「✍️ 我的筆記」和你自己的 frontmatter 都保留；Notion 只替換標題為「📚 ZotMax｜…」的那個區塊。改了 Citation key 或標題，外掛靠 `zotero_key` 找到原本的筆記並改檔名；你把筆記搬到規則資料夾底下的其他子資料夾也找得到。

**文獻筆記的版面**：最上面是 10 秒看完的「重點」（一句話、研究設計 · 樣本數 · 證據等級 · 評讀結果、2–3 個主要發現、你的重點劃線、全文與 Zotero 的連結），其餘收在固定順序的摺疊區塊。Notion 也是「重點」加收合區塊。

- **閱讀狀態**：待讀／閱讀中／已讀／已引用，在 Zotero（標籤）、Notion（`閱讀狀態` 欄位）、Obsidian（`status`，可在看板拖曳）任一邊改，下次同步另外兩邊跟著改。右側面板也能直接改。→ 設定 → 同步 → 閱讀狀態
- **自動同步**（選用，預設關閉）：條目、劃線或筆記變更後自動同步。**自動同步不會呼叫 AI。** → 設定 → 同步 → 自動同步
- **中途停止與接續**：一次同步很多篇時，工具 → **停止 ZotMax 同步**；之後 **繼續未完成的 ZotMax 同步（N 筆）**。Zotero 關閉或當掉也不會從頭來過，失敗的會一起重試。
- **圖片劃線**：在 PDF 用「選取區域」框選的表格、圖和手繪註記，連同截圖一起同步（Obsidian 存在 `attachments/`，Notion 上傳成圖片）。
- **中文 APA**：中文期刊、學位論文自動改用中文 APA 7（`陳美玲、林小華（2023）。題目。護理雜誌，70(2)，45–56。`，內文「陳美玲等，2023」），參考文獻可以中文在前。→ 設定 → 同步 → 中文文獻與中文 APA

<summary>文獻筆記的版面（Obsidian 範例）</summary>

```markdown
> [!abstract] 重點
> **一句話**：護理師帶的運動課讓住院長者跌倒率下降 30%。
>
> RCT · N = 120 · CEBM 2 · JBI 1.c · 評讀：納入（AI 初評）
>
> **主要發現**
> - 跌倒率下降 30%
> - 遵從度高、沒有嚴重不良事件
>
> **我的劃線**
> - ==🟡reduced the rate of falls by thirty percent== 重要發現 · [p. 2](zotero://…)
> - ==🔴no serious adverse events were reported== 限制／疑問 · [p. 2](zotero://…)
>
> [[Zotero/全文/lee2024|全文與劃線]] · [Zotero](zotero://…) · [Notion](https://…) · [DOI](https://doi.org/…)

> [!quote]- 🟡 重要發現（1）
> [!quote]- 🔴 限制／疑問（1）
> [!note]- 我的 Zotero 筆記（1）
> [!example]- 文獻評讀表
> [!tip]- AI 標的重點（僅供參考）
> [!note]- AI 文獻筆記（模型 · 日期）
> [!info]- 摘要（Abstract）
> [!search]- 🔎 延伸搜尋
> [!info]- 書目資訊
```

- **重點**：評讀結果以核對過的評讀表優先（標「已核對」），只有 AI 的標「AI 初評」；「我的劃線」依顏色意義的順序，每種意義先挑一條，最多 3 條。沒有 AI 筆記或劃線時，這裡會說明產生後會出現什麼。
- **摺疊區塊**：先放你的東西（各顏色的劃線、Zotero 子筆記、評讀表），再放 AI 的，最後是參考資料。沒有內容的區塊不出現。一句話和 Zotero／Notion 連結只出現在「重點」；全文不貼進筆記，用連結開全文筆記。
- **Notion**：每一段是一個收合區塊，劃線分組帶著該顏色的底色。

</details>

<details>
<summary>閱讀狀態：存在哪裡、以哪邊為準</summary>

| 地方 | 存在哪裡 | 怎麼改 |
|---|---|---|
| Zotero | 標籤 `狀態/已讀 ✅`（每篇只留一個） | 右側面板的「閱讀狀態」選單，或直接改標籤 |
| Notion | `閱讀狀態`（舊資料庫：`Status`）單選欄位 | 在資料庫改 |
| Obsidian | frontmatter 的 `status` | 在「閱讀進度」看板拖曳，或直接改 |

- **什麼時候同步**：每次一般同步都會比對三邊。自動同步只在 Zotero 有變更時觸發，所以 Notion／Obsidian 的改動會在下次同步時帶回；想一次更新全部，用 ZotMax 按鈕或快速指令 → **同步閱讀狀態**（只更新已同步過的文獻的狀態，不呼叫 AI、不新增 Notion 頁面）。
- **以哪邊為準**：外掛記得上次三邊一致的狀態（Obsidian 的 `status_synced`；沒設定 Obsidian 時記在 Zotero 設定）。只有一邊改過就以那邊為準；不同地方改成不同狀態時，依 **Obsidian > Zotero > Notion**，進度視窗顯示「⚠️ 閱讀狀態衝突」。自動同步時改以 Zotero 優先。
- 只同步到 Obsidian 或只同步到 Notion 時，沒選的那邊下次一般同步再補上。
- 移到 Zotero 垃圾桶的文獻不會被狀態同步恢復；「已刪除」只由外掛設定。
- **標籤**：前綴可以改（舊標籤不會自動改名）。標籤含 emoji（預設：閱讀中 📖、已讀 ✅、已引用 📝）時，Zotero 會顯示在標題旁。替狀態標籤指定顏色後，可以用數字鍵快速標記；同時有兩個狀態標籤時，同步會留下新加的那個。
- **為什麼 Notion 用「單選」**：Notion API 不能把選項放進「狀態」類型的分組，也不能填入還不存在的狀態選項。資料庫原本就有「狀態」類型的 `Status` 欄位時外掛不會動它，會提示你改名後再按「測試連線並補齊資料庫欄位」。
- 不想同步閱讀狀態：關掉「閱讀狀態」開關（Zotero 不會再加標籤）。

</details>

<details>
<summary>自動同步、刪除的條目與中途停止</summary>

- **刪除條目**：條目移到 Zotero 垃圾桶或刪除時，Notion 頁面移到 Notion 垃圾桶；Obsidian 筆記**不會刪除**，只把 `status` 改成「已刪除」並在區塊最上方加提示。從垃圾桶還原再同步，筆記恢復原本的狀態（Notion 會建新頁面）。
- **停止**：正在處理的那一篇完成後才停，不會留下寫到一半的筆記。
- **Zotero 關閉或當掉**：下次開啟會提醒還有幾筆沒同步，從工具選單接續；不想接續就選 **放棄未完成的 ZotMax 同步**。
- 開始新的多篇同步時會取代上一次未完成的紀錄；單篇同步和自動同步不記錄。
- 選「同步到兩邊」但只設定了一邊時，沒設定的那邊自動略過。某一步失敗（例如 AI 逾時）時，其他步驟照常完成。

</details>

<details>
<summary>圖片劃線：檔名、刪除、Notion 上傳</summary>

- **Obsidian**：截圖存在筆記所在資料夾的 `attachments/<條目KEY>-<註記KEY>.png`，嵌入對應顏色的劃線區，上方是頁碼連結、下方是你的評註。內容沒變不重寫；用條目 KEY 命名，所以改 citekey 也不用改名。
- **刪除**：在 Zotero 刪掉圖片劃線後再同步，對應的截圖會刪除。只刪這篇文獻 `條目KEY-註記KEY.png` 格式的檔案，你自己放的圖片不會動；筆記搬到別的資料夾後，舊的截圖不會跟著搬。
- **Notion**：用檔案上傳 API 上傳成圖片區塊。上傳的檔案沒馬上放進頁面一小時後就失效，而自動同步區每次重建，所以**每次同步到 Notion 都會重新上傳**（每張圖多 2 次 API 請求）。單檔上限 20 MB（Notion 免費方案 5 MB）；失敗時頁面照常同步，只是少了圖。
- **截圖從哪來**：Zotero 的快取；沒有時請 Zotero 當場從 PDF 產生，產生不了（例如這台電腦沒有 PDF）就保留顏色、頁碼與評註。
- **AI 也看圖片劃線**（設定 → AI → AI 服務 → AI 文獻筆記，預設關閉）：把截圖一起傳給 Claude 讀表格裡的數字。一次最多 20 張，單張超過約 3.7 MB 或 8000 像素略過；OpenAI 不送圖片。評註文字不論如何都會送給 AI。
- 不想要截圖：關掉「圖片劃線」開關。

</details>

### 整理

- **文獻自動分類**：依研究設計／證據等級、你列的主題、你寫的規則和 PICO，建議把文獻放進哪些 Zotero 子分類（例如 `自動分類/研究設計/RCT`）。每項建議標明來源與信心，你勾選後按「套用」才寫進 Zotero；只會新增子分類和加入文獻，不會移出文獻或改你原本的分類。ZotMax 按鈕或快速指令 → **復原上次分類** 可以整批復原。主題要 AI 判斷（「AI 主題分類」開關）。→ 工具列「整理」、條目或分類右鍵、設定 → 整理 → 文獻自動分類
- **研究儀表板**：Obsidian 裡一頁 `研究儀表板.md`，看閱讀進度、證據等級分布、待讀最久與資料待補的文獻、回顧專案的 PRISMA 篇數、AI 用量和本週新增。只讀 vault，不連網、不花錢。→ ZotMax 按鈕或快速指令 → **更新研究儀表板**（預設手動同步後也會更新）
- **概念卡片**：把 AI 筆記「關鍵概念」裡的 `[[概念]]`（也可加上測量工具、結果指標）整理成 `Zotero/概念/` 的卡片：別名、MeSH／PubMed 連結、提到它的文獻表、常一起出現的概念，加上「概念索引」與 Mermaid 關係圖。→ ZotMax 按鈕或快速指令 → **更新概念卡片**、設定 → 整理 → 概念卡片（Obsidian）
- **全文筆記**：每篇文獻旁多一份 `Zotero/全文/<同檔名>.md`，由 Zotero 已抽出的文字整理成 Markdown（接回斷字、分段、標出 Abstract／Methods／Results 等段落、去掉頁首頁尾），你的劃線依顏色標在原文。它每次同步都重新產生，**想法請寫在文獻筆記**。→ 設定 → 整理 → 全文筆記
- **劃線顏色有意義**：Zotero 的 8 種劃線顏色各代表一種意義（預設黃＝重要發現、紅＝限制／疑問…），筆記裡的劃線依意義分組。→ 設定 → 整理 → 劃線顏色與意義

<summary>文獻自動分類：四個面向、規則語法、放在哪裡、復原</summary>

**怎麼開始**：條目或分類右鍵 → **ZotMax ▸ 文獻自動分類（所選文獻或目前分類）…**（分類含子分類）；或 ZotMax 按鈕或快速指令 → 同一項。

**確認視窗**：每篇列出建議的子分類（核取方塊），每一項寫出來源與信心，例如「規則推測・高｜標題有「randomized」」「AI 筆記・中｜AI 筆記的證據等級，請對照原文確認」「你的規則・高｜符合第 2 行：…」。信心高的和規則符合的先勾好，信心低的先不勾。下方即時顯示「已勾選 N 項：會建立 X 個子分類，加入 Y 筆」。按 **套用** 才寫進 Zotero；按取消（或 Esc）什麼都不改。

**放在哪裡**：預設在文獻庫最上層建立 `自動分類`，底下依面向分資料夾：

```
自動分類/
  研究設計/   RCT、Quasi-experimental、Cohort、Case-control、Cross-sectional、Qualitative、Mixed methods、
              Systematic review & meta-analysis、Scoping review、Guideline、其他設計
  證據等級/   CEBM Level 2、JBI Level 1.c …
  主題/       你列的主題
  規則/       你寫的規則名稱
  族群 P/、介入 I/、結果 O/
```

上層名稱和位置可以改（例如放在 `碩論/文獻回顧` 底下；找不到時確認視窗會說明並改放最上層）。名稱相同（不分大小寫、全半形）的子分類會沿用，同一篇可以在好幾個子分類裡。

**四個面向**（各自可在設定關掉）：

- **研究設計與證據等級**：有 AI 筆記就用它的結構化資料，不另外花錢。沒有時從 Zotero 標籤與 Extra（例如 PubMed 的 Publication Type；MeSH 的「… as Topic」不算）、標題、摘要找設計的關鍵字，標「規則推測」：標籤與標題信心高；摘要只有一種設計信心中，提到好幾種信心低、不先勾。**證據等級只取自 AI 筆記**，不用猜的。
- **自訂主題**（要打開「AI 主題分類」，會產生費用）：一行一個主題，冒號後可寫說明或關鍵字，例如 `跌倒預防: 跌倒、fall prevention、hip protector`。AI 只看標題、摘要和一句話摘要，一次判斷 10 篇；送出前顯示篇數、呼叫次數與預估費用，可以「用 AI 判斷主題」「跳過主題，只看其他建議」或「取消分類」。清單外的主題會被忽略並告訴你。沒開開關、沒有 API key 或 AI 失敗時，確認視窗最上方寫明原因，其他面向照常。
- **規則**（不用 AI，結果每次都一樣）：一行一條 `子分類名稱 = 條件`：

  ```
  跌倒 = title:falls OR tag:跌倒
  近五年 RCT = year>=2021 AND (title:randomized OR tag:"Randomized Controlled Trial")
  中文文獻 = language:zh
  非質性 = NOT (title:qualitative OR abstract:質性)
  ```

  - 欄位：`title:`、`abstract:`、`journal:`、`author:` 包含這個字就符合；`tag:` 要完全相同，結尾加 `*` 比對開頭（`tag:篩選/*`）；`year>=2020`、`year<2015`、`year=2020`、`year:2018-2022`；`language:zh`（沒填語言但標題是中文也算）、`language:en`；`type:journalArticle`、`type:thesis` 或 `type:學位論文`。也可以用中文欄位名：標題、摘要、標籤、期刊、年份、語言、類型、作者。
  - 不寫欄位的字詞在標題和摘要裡找；有空格的詞用引號（`"fall prevention"` 或「」）。不分大小寫和全半形。
  - `NOT` 先算，再 `AND`，最後 `OR`；不確定就加括號。兩個條件中間沒寫運算子就是 `AND`。`#` 開頭的行是註解。
  - 設定頁即時檢查，寫錯的行會標出「第 N 行：少了右括號 )」這類說明；執行時略過並提醒。
- **PICO**：取自 AI 筆記的族群 P、介入 I、結果 O（以頓號、逗號拆開，沒有 outcomes 時用 measures）。不同寫法會合併，並沿用 設定 → 整理 → 概念卡片 的「同義詞合併」。只有一篇用到、又沒有同義詞或既有子分類的說法先不勾，免得子分類太零碎。沒有 AI 筆記的文獻沒有 PICO 建議。

**復原**：ZotMax 按鈕或快速指令 → **復原上次分類** 把最後一次套用加入的文獻從那些子分類移出，並刪除那次新建、現在又是空的子分類（你後來放了東西的會保留並告訴你）。只能復原最後一次；關掉「文獻自動分類」後仍然可以用。

</details>

<summary>概念卡片：同義詞合併、卡片內容、AI 綜整</summary>

- **從哪裡來**：只看文獻筆記自動區塊裡「關鍵概念」的 `[[…]]`（你在「✍️ 我的筆記」寫的連結不算）；預設也把測量工具（`measures`）做成卡片，可選擇加上結果指標（`outcomes`）。只讀 vault，不連網、不呼叫 AI；沒有任何概念時不建立檔案。

- **概念索引**（`概念/概念索引.md`）：全部概念依文獻數排序，加上前 15 個概念的 Mermaid 關係圖。

- **卡片不會被刪除**：沒有文獻再提到的概念，卡片改成「目前沒有文獻筆記提到這個概念」，`papers` 設為 0，要不要刪由你決定。

<summary>全文筆記：怎麼轉換、送給 AI 的全文、Notion 子頁面、markitdown</summary>

- **檔案**：寫在文獻筆記所在資料夾的 `全文/` 子資料夾（名稱可改），最上面有提示框並連回文獻筆記；文獻筆記的 frontmatter 有 `fulltext: "[[Zotero/全文/lee2024]]"`。它沒有 `zotero_key`，不會出現在 Bases 總表、儀表板與概念卡片。文獻筆記改名時跟著改名；同名但不是外掛產生的檔案不會被覆寫。
- **怎麼轉成 Markdown**：用 Zotero 已抽出的全文，不用另外裝東西。接回行尾斷字（`interven- tion` → `intervention`，`self-reported` 這類保留連字號）、跨頁段落接回、整行是段落名稱的才當標題（Abstract、Background、Methods、Results、Discussion、Conclusion(s)、Limitations、References、Acknowledgements、Funding、Conflict of interest；摘要、前言、緒論、研究方法、結果、討論、結論、研究限制、參考文獻、誌謝），刪掉多頁重複的頁首／頁尾和頁緣頁碼。不確定的就保留。
- **劃線標在原文**：依顏色標成 `==🟡…==`，比對時忽略換行、斷字與少數字的差異；對不上的（跨頁、圖表裡的字、掃描檔）列在檔案最後，不會遺失。
- **送給 AI 的全文**：產生 AI 筆記時改送這份 Markdown，並先刪掉 References、Acknowledgements、Funding、Conflict of interest（設定可關；印在參考文獻後面的表格與圖保留）。進度視窗會顯示省下多少（見[隱私與費用](#隱私與費用)）。
- **Notion 全文子頁面**（預設關閉）：在文獻頁面底下建「全文：標題」子頁面，劃線變成對應的底色。一篇通常要 5–10 次 API 請求，同步會變慢；內容有變時舊子頁面移到垃圾桶、建新的（連結會變）。
- **快取**：依附件、修改時間與大小快取在 Zotero 資料夾的 `zotero-bridge/fulltext/`，重新同步不會重做。
- **掃描版 PDF**：沒有文字層就沒有全文筆記，先 OCR。

**markitdown（選用）**：[markitdown](https://github.com/microsoft/markitdown) 是 Microsoft 的開源轉換工具，要自己安裝（`pip install 'markitdown[pdf]'`），然後在 設定 → 整理 → 全文筆記 →「選用：用 markitdown 轉換 PDF」填執行檔路徑（只填 `markitdown` 會在 PATH 裡找）。老實說它能幫的有限：表格、表單類的頁面會保留成 Markdown 表格，其餘頁面輸出純文字；一般論文的段落標題它不會標（仍由外掛偵測），掃描檔也不會 OCR。執行失敗、超過 2 分鐘或輸出超過 8 MB 時自動改用內建轉換，進度視窗會說明（同一個檔案不會每次重試）。

</details>

### 找文獻

- **醫學文獻快速搜尋**：內建 PubMed、Cochrane、CINAHL、Embase、Google Scholar、華藝、臺灣博碩士論文等 21 個資料庫（可自訂、可設學校的 EZproxy）。出現在四個地方：條目右鍵 **ZotMax ▸ 在醫學資料庫搜尋**（找這篇、PubMed 相似文獻）、右側面板的搜尋連結與 PICO 檢索連結、筆記的「🔎 延伸搜尋」（找這篇、MeSH、PICO 檢索式），以及 ZotMax 按鈕或快速指令 → **醫學文獻快速搜尋…**（輸入關鍵字，英文會建議 MeSH 主題詞）。檢索式還是你自己決定。→ 設定 → 醫學文獻快速搜尋
- **PubMed 新文獻追蹤**（研究生引導預設關閉）：存好 PubMed 檢索式（可用 MeSH），手動或定期把新文獻用 Zotero 內建匯入器匯入指定分類，不會重複匯入，並在 Obsidian 產生每日清單。→ ZotMax 按鈕或快速指令 → **檢查新文獻（PubMed 追蹤）**、設定 → PubMed 新文獻追蹤
- **引文追蹤**（研究生引導預設關閉）：從納入研究用 [OpenAlex](https://openalex.org)（免費、不需 API key）往回查參考文獻、往前查引用它的文獻，去重後列成 Obsidian 勾選清單與 CSV；**只列候選，不自動匯入**，勾選的再一鍵匯入。→ 工具列「找文獻」、分類右鍵 → **ZotMax：引文追蹤**
- **網頁版搜尋**：[bobyu89.github.io/zotero-bridge/search.html](https://bobyu89.github.io/zotero-bridge/search.html)，不用 Zotero、手機也能用，含 PICO 檢索式產生器。

<summary>醫學文獻快速搜尋：四個入口的細節與範例</summary>

**1. 條目右鍵 → ZotMax ▸ 在醫學資料庫搜尋**：找這篇在各資料庫的紀錄。
- PubMed：有 PMID（Extra 的 `PMID: …`）直接開該篇；沒有用 DOI；再沒有用題名的每個字（`Hospital[ti] AND nurse[ti] …`，最多 10 個字）。整句題名加引號在 PubMed 只比對片語索引，實測找不到原文，所以不用。
- Europe PMC 用 PMID／DOI／題名；CINAHL 用 `TI "題名"`；其他用加引號的題名。有 PMID 時多一項 **PubMed 相似文獻**。
- 選單只列前 8 個（可改），其他在「**更多資料庫…**」，可以連續開好幾個。中文題名只列中文與跨語言的資料庫。

**2. 右側面板**：ZotMax 面板的「延伸搜尋」有搜尋連結一列；有 AI 筆記且有 PICO 時，下一列是 **PICO 檢索連結**（PubMed、CINAHL、Google Scholar）和「複製檢索式」。

**3. 筆記的「🔎 延伸搜尋」**（收合區塊，Notion 也有）：找這篇、相似文獻、**MeSH**（從 PubMed 匯入的 MeSH 標籤，連到 MeSH Database 與 `"主題詞"[Mesh]` 搜尋；`Humans`、`Aged` 這類檢查標籤略過）、**PICO 檢索式**（`P AND I AND O`，同一欄多個詞用 OR，設定可加入 C）。AI 筆記的 PICO 是中文（術語保留英文），所以英文檢索式只取英文詞，缺的欄位會提醒你補；另有中文原樣的版本連到 Google Scholar。

**4. ZotMax 按鈕或快速指令 → 醫學文獻快速搜尋…**：輸入關鍵字（不同概念用逗號分隔，例如 `fall prevention, older adults`），選資料庫開啟，開完回到清單。
- **英文關鍵字**：先向 NCBI 查 MeSH 建議，例如 `falls, older adults` 組成 `("Accidental Falls"[Mesh] OR falls[tiab]) AND ("Frail Elderly"[Mesh] OR "Aged"[Mesh] OR "older adults"[tiab])`；可以「複製 PubMed 檢索式」或「**存成 PubMed 新文獻追蹤**」。查不到時用原本的關鍵字。
- **中文關鍵字**：華藝、博碩士論文、國圖期刊、衛福部／國健署排前面。
- MeSH 建議只是起點，請到 MeSH Database 看 Scope Note 與樹狀結構確認。「主題＋目的」的片語（`fall prevention`）常查不到，改用核心詞（`falls`）就會對到 `Accidental Falls`。

**範例**
- 寫實證報告：`pressure injury, repositioning` → 先開 PubMed（MeSH 檢索式），再開 Cochrane、CINAHL、TRIP，最後存成 PubMed 追蹤。
- 中文文獻：`壓力性損傷 翻身` → 選華藝，在開啟的頁面貼上（Ctrl+V／⌘V）；再選臺灣博碩士論文系統。
- 讀到好研究：在筆記展開「🔎 延伸搜尋」→ 點 PICO 的 PubMed 連結或「相似文獻」。

<summary>醫學文獻快速搜尋：設定、EZproxy、自訂資料庫</summary>

- **資料庫順序**：ID 以逗號分隔，例如 `pubmed, cinahl, cochrane, airiti, scholar`。**隱藏的資料庫**：例如 `embase, uptodate`。設定頁下方列出所有 ID 與狀態。
- **自訂資料庫**（JSON 陣列）：`name`、`url`（`{q}` 換成檢索詞；沒有 `{q}` 的網址會開啟並複製檢索詞）、`needsAccess`（`true` 才套用代理）。選填：`id`（用內建 ID 可改內建資料庫）、`query`（檢索詞外框，例如 `"{q} AND nursing"`）、`find: true`（也用來找這篇）、`lang`（`zh`／`en`／`any`）。

  ```json
  [
    { "name": "學校館藏查詢", "url": "https://<學校的館藏系統>/search?q={q}", "needsAccess": false },
    { "id": "cinahl", "url": "https://search.ebscohost.com/login.aspx?direct=true&db=ccm&bquery={q}&type=1&site=ehost-live" }
  ]
  ```

- **圖書館代理伺服器前綴（EZproxy）**：填了之後，**只有需要機構權限的資料庫**（CINAHL、Embase、JBI、UpToDate 與 `needsAccess: true` 的自訂資料庫）經由代理開啟，在校外也能用學校帳號登入；例外填在「不套用代理的資料庫 ID」。前綴通常是 `https://<代理伺服器>/login?url=`（也支援 `…?qurl=` 與含 `{url}` 的前綴）。怎麼找：
  1. 學校圖書館網站的「校外連線」「遠端存取」說明頁；
  2. 或在校外從圖書館的電子資料庫清單點一個資料庫，看網址列：`https://xxx.yyy.edu.tw/login?url=https://search.ebscohost.com/…` 的前綴就是 `https://xxx.yyy.edu.tw/login?url=`；
  3. 學校用 VPN 或 OpenAthens（網址裡沒有 `login?url=`）就留空，連上 VPN 後直接用。不確定請問圖書館。
- 其他：右鍵選單最多列出幾個（1–8）、右側面板的搜尋連結、筆記的「🔎 延伸搜尋」、PICO 包含對照組（C，預設不含：C 常是「常規照護」，加進去會漏掉很多文獻）、MeSH 建議（預設開啟；關掉就不連 NCBI）。

<summary>PubMed 新文獻追蹤：設定、匯入規則、每日清單</summary>

**1. 設定**：設定 → 找文獻 → PubMed 新文獻追蹤 →「新增追蹤」：

| 欄位 | 說明 |
|---|---|
| 名稱 | 例如「跌倒預防」，成為標籤 `追蹤/跌倒預防` |
| PubMed 檢索式 | 和 PubMed 網站一樣的語法，例如 `("Accidental Falls"[Mesh]) AND nurs*[tiab]`；建議先在網站調好再貼上 |
| 存到 Zotero 分類 | 留空 = `📥 新文獻/<名稱>`；可填 `碩論/新文獻`，沒有的分類會自動建立 |
| 第一次檢查回溯天數 | 預設 30 天；之後只查上次檢查以後的 |
| 只要出版日期在此之後（選填） | 例如 `2020` 或 `2023/01/01` |

按「測試檢索式」看符合篇數、最近新增的篇數，以及 PubMed 怎麼解讀你的檢索式（拼錯的 MeSH 詞會顯示警告）。

- **NCBI（PubMed）連線**：Email（NCBI 要求附上聯絡信箱，只送給 NCBI）；NCBI API key（選填，每秒查詢從 3 次提高到 10 次，存在密碼管理員）。MeSH 建議也用這組設定。
- **每個追蹤每次最多匯入**：預設 50 篇（最多 200），其餘排隊（最多 500 篇）下次繼續。
- **自動檢查**（預設關閉）：Zotero 啟動約 2 分鐘後與之後每小時看一次，距上次檢查超過設定時數（預設 24 小時）才查，所以一天開關很多次也不會重複查。
- **每日新文獻清單**（預設開啟）；**手動檢查後產生 AI 筆記**（預設關閉，超過 5 篇先顯示費用預估）。**自動檢查一律不呼叫 AI。**

**2. 檢查**：ZotMax 按鈕或快速指令 → **檢查新文獻（PubMed 追蹤）**，或設定頁「立即檢查全部」。自動檢查不顯示進度視窗，有新文獻或錯誤才通知。

**3. 匯入的文獻**：
- 用 Zotero 內建的 PubMed 匯入器建立條目（和魔術棒輸入 PMID 一樣），書目完整，Extra 有 `PMID: …`。不附 PDF，需要時用 Zotero 的「尋找全文」。
- 加上標籤 `新文獻`、`追蹤/<名稱>`、`來源/PubMed`（PRISMA 計數會算進 PubMed 來源）。
- **不會重複匯入**：已有相同 PMID 或 DOI 的略過；外掛記得每個追蹤看過的 PMID，你丟進垃圾桶的不會再回來。兩個追蹤找到同一篇只匯入一次。
- 單篇匯入失敗下次重試，連續 3 次失敗就放棄（進度視窗列出 PMID）。某個追蹤出錯時，下次從原本的時間點重查，其他追蹤照常。

**4. Obsidian 每日清單**：`<預設子資料夾>/新文獻/YYYY-MM-DD.md`，依追蹤分段，每篇一行待辦（標題、期刊、年份、Zotero／DOI／PubMed 連結）。同一天再檢查只加新的，已勾選的項目和區塊外的筆記保留。

**注意**：依「加入 PubMed 的日期」（Entrez Date）查詢，晚收錄的舊文獻也會出現，只要近年的請填出版日期限制。匯入一律存到「我的文獻庫」。改了檢索式仍從上次時間點開始；想重新回溯就刪掉追蹤再新增。

<summary>引文追蹤：查詢、候選清單、匯入、PRISMA</summary>

PRISMA 2020 要求報告「其他方法」找到的文獻，最常見的就是引文追蹤：查納入研究的參考文獻（往回）與引用它們的文獻（往前）。

**1. 查詢**：全文篩選有了「全文：納入」之後，分類右鍵 → **ZotMax ▸ 引文追蹤：目前分類全文納入的研究**（或工具列「找文獻」、快速指令）。也可以選幾篇文獻 → 右鍵 → **ZotMax ▸ 引文追蹤所選文獻（OpenAlex）**。
- 以 DOI（或 Extra 的 PMID）找到該研究，兩者都沒有的標「沒有 DOI 或 PMID，無法查詢」。
- 背景查詢（每秒最多 5 次），不卡住 Zotero。每次最多 100 次請求，每篇每個方向最多 200 篇（依被引次數排序），超過時標「已達上限」。可在 設定 → 找文獻 → 引文追蹤（OpenAlex） 調整，也可以只查往回或往前。
- 建議填 email：OpenAlex 會把帶 email 的請求放到較穩定的 polite pool（只送給 OpenAlex）。

### 篩選與評讀

- **篩選與 PRISMA 2020**：一個回顧專案就是一個 Zotero 分類。在條目上按右鍵（或右側面板的按鈕）標記標題摘要與全文的納入／排除（排除原因可自訂），決定存成 Zotero 標籤；找出可能重複的文獻；一鍵產生 PRISMA 2020 計數、Mermaid 流程圖、一致性檢查與納入研究的證據表（Obsidian 筆記 + Excel 可開的 CSV，可選 Notion 頁面）。**決定由你做**，外掛只記錄與計數。→ 右鍵 **ZotMax：篩選（系統性／範圍回顧）**、分類右鍵 **ZotMax：系統性回顧篩選**
- **文獻評讀表**：右側面板逐題點選 是／否／不清楚／不適用，寫評析根據，可選 CASP 或 JBI 清單；AI 筆記的嚴格評讀會預先帶入並標「AI 初評」。勾選「我已核對」後，你的評讀取代 AI 的值，同步到筆記、PRISMA 證據表與實證報告草稿。可加第二位評讀者算 Cohen's κ，並匯出分類的評讀總表（燈號矩陣、CSV、Word）。→ 右側面板「文獻評讀表」、分類右鍵 **ZotMax：匯出文獻評讀總表**
- **評讀陪練**：先自己答完評讀表，再按「對照 AI」看 AI 只讀原文會怎麼答；只列出跟你不同的題目，由你決定保留或修改。見[下方](#評讀陪練)。
- **評讀表網頁**：不用 Zotero 也能評讀，見[下方](#評讀表網頁)。

清單題目是外掛的中文意譯，**不是官方原文**；評讀時請開官方表單對照，報告中引用官方清單。

<summary>篩選：來源標籤、找重複、篩選標籤、PRISMA 產出與注意事項</summary>

**1. 標記資料庫來源（選用）**：匯入時替文獻加標籤 `來源/PubMed`、`來源/CINAHL`…（可以全選該批文獻拖到標籤上）。沒有來源標籤時用條目的「圖書館目錄」（Library Catalog）欄。

|---|---|

- **CSV** `Zotero/Reviews/<分類> 證據表.csv`（UTF-8 BOM，Excel 不亂碼），欄位更多。
- **Notion**（選用）：填「PRISMA 頁面的 Notion 父頁面」（留空用文獻比較表的父頁面），同一個分類一直更新同一頁。

- 同一篇在 Zotero 只有一組標籤，放在兩個回顧專案會共用篩選決定；需要各自決定時請用不同的文獻庫（例如群組文獻庫）。
- 流程圖是新版 systematic review 的版本。`來源/引文追蹤`、`來源/網站`、`來源/機構`（設定「其他方法的來源」可改）算在右側「其他方法」欄，直接給全文決定不會警告；有重複或標題摘要排除時會多一個 Records excluded 框讓數字對得起來（PRISMA 範本沒有這個框，可自行刪除）。外掛分辨不出同一研究的多篇報告，「Studies included」與「Reports of included studies」顯示相同數字，需要時請手動改。

- `<分類> 評讀總表.md`：評讀概況、**燈號總表**（每份清單一張表，✅ 是 ❌ 否 ❓ 不清楚 ➖ 不適用 ⬜ 未評）、各篇評讀表、雙人評讀一致性、沒有評讀的文獻。

- `<分類> 評讀總表（Word）.md`：在同一資料夾執行 `pandoc "<分類> 評讀總表（Word）.md" -o "<分類> 評讀總表.docx"` 轉成 Word。

**Cohen's κ 怎麼算**：只計入兩人都作答、不是開放式的題目，答案分是／否／不清楚／不適用四類。p_o = 答案相同的題數 ÷ 題數；p_e = Σ（A 選該類的比例 × B 選該類的比例）；κ = (p_o − p_e) ÷ (1 − p_e)。兩人都只用同一類答案時 p_e = 1，κ 無法計算（只顯示一致率）。解讀依 Landis & Koch（1977）：≤ 0.20 輕微、0.21–0.40 尚可、0.41–0.60 中等、0.61–0.80 高度、> 0.80 幾乎完全一致。題數少時 κ 不穩定，請搭配一致率與不一致清單討論。

#### 評讀陪練

先自己做，再看 AI。打開「評讀陪練」開關（進階預設開；要先開「文獻評讀表」和「AI 文獻筆記」，並設定 API key）後：

1. 在評讀表自己答完每一題（AI 初評帶入的題目要點一下你的答案確認，或勾「我已核對」）。還沒答完時「對照 AI」是灰的，滑鼠停在按鈕上會告訴你還差哪幾題。
2. 按「對照 AI」（評讀表裡、面板「狀態」那一列、「動作」或快速指令 **評讀陪練：對照 AI**）。先顯示預估費用，確認後才送出，並會先儲存評讀表。
3. AI 只拿到這篇的全文（和 AI 筆記一樣整理過、刪掉參考文獻；沒有全文時改用摘要，並先告訴你）和評讀工具的題目，**看不到你的答案和評析**；它逐題回答、寫 1–2 句理由並引用原文。比對差異的是 ZotMax，不是 AI。
4. AI 的引文會回全文核對：核對不到的直接略過（顯示略過幾句），一題沒有任何可核對的引文時標「低可信（無原文佐證）」。核對到的引文標出 PDF 頁數，點一下就在那一頁打開 PDF。
5. 評讀表只列出 **AI 跟你不同的題目**：你的答案、AI 的答案、AI 的理由與原文。每題選「保留我的判斷」或「改成 AI 的答案」，可以寫一句「為什麼」。一致的題目折在下面，想看也看得到。上方一行「13 題中 11 題一致，2 題不同（一致 85%）」。

你的答案只有在按「改成 AI 的答案」時才會改。每次對照（日期、模型、評讀工具、每題 AI 的答案、理由、核對過的引文，以及你的決定和時間）都記在「📝 文獻評讀表」子筆記的 JSON 裡（保留最近 5 次）；同步到 Obsidian／Notion 的評讀區塊只多一行「評讀陪練：一致 11/13，修改 1 題」，AI 的答案不會當成你的評讀。AI 的答案只是另一個角度，不是標準答案；不同的地方正好是回原文再讀一次的地方。

### AI 輔助與寫作

AI 功能要開關打開、也設定了 API key 才會用到。所有 AI 產出都是**初稿**：每個數字、每個引用都要對照原文。

- **AI 文獻筆記**：同步時（沒有 AI 筆記才產生）請 AI 讀書目、摘要、全文和你的劃線與筆記，寫成固定格式的研讀筆記：一句話摘要、背景與目的、設計與方法（樣本、工具信效度、統計）、主要結果、作者結論、研究限制、嚴格評讀（依研究設計選 JBI 或 CASP 清單逐題作答，給整體評價）、證據等級、對我研究的啟發、關鍵概念 `[[ ]]`、可引用句。AI 筆記存回 Zotero 子筆記，之後同步不再花 token，你也可以直接在 Zotero 修改。→ 工具列「AI 輔助與寫作」→ **重新產生 AI 筆記並同步**；右側 ZotMax 面板的「重點」可直接看摘要與主要發現
- **研讀欄位**：AI 同時輸出研究設計、樣本數、場域、PICO、測量工具、證據等級（Oxford CEBM 2011 與 JBI）、評讀結果、國家，寫進 Notion 欄位與 Obsidian frontmatter，可以篩選「研究設計 = RCT 且樣本數 > 100」。
- **可引用句查證**：每一句都和全文、摘要、劃線比對，找到標 ✅，找不到標 ⚠️。
- **AI 標重點**（研究生引導預設關閉）：同一次呼叫順便挑 3–6 句關鍵原句，和全文核對後在全文筆記用「🤖＋底線」標出，跟你的彩色劃線分開，僅供參考。
- **文獻比較表**（預設關閉）：選 2 篇以上或整個分類，AI 讀各篇 AI 筆記，產生比較表、主題整理、方法學品質與研究缺口，存成 Obsidian、Zotero 獨立筆記和 Notion 頁面。→ **產生文獻比較表（AI）**
- **文獻探討草稿**（預設關閉）：依你填的研究問題與主題大綱，把一個分類寫成第二章的草稿。AI 只能用 [S#] 代號引用，由外掛換成 citekey，附數字查核清單與 Pandoc 指令。→ **產生文獻探討草稿（AI）**
- **實證報告草稿**（預設關閉）：依台灣護理學會 A 類實證健康照護綜整文章的架構，PICO 表、搜尋策略、PRISMA 流程圖與證據表由外掛依你的資料產生，AI 寫敘述與逐篇評讀，附查核清單與評分項目自我檢核。→ **產生實證健康照護報告草稿（AI）**
- **進度報告**（預設關閉）：和指導教授開會前，整理兩次會議之間讀完哪些文獻、PRISMA 計數變化、草稿字數、下次目標。資料都來自 Zotero 與 vault，**不需要 AI**；AI 摘要可選。→ ZotMax 按鈕或快速指令 → **產生進度報告（給指導教授）**
- **讀懂統計**（研究生引導預設關閉）：在 PDF 閱讀器選一段文字，選取框裡按 **ZotMax：解釋統計**（或快速指令 → **解釋所選統計**），右側 ZotMax 面板多出「統計解釋」。詳見下方「讀懂統計」。
- **研究大腦**：[`research-brain/`](research-brain/README.md) 是給 Obsidian vault 用的 Claude Code／Codex CLI 設定檔，用斜線指令做跨文獻的工作（`/lit-compare`、`/research-gaps`、`/lit-review-draft`、`/inbox-triage`、`/review-prisma`）。外掛負責每一篇的固定流程，研究大腦負責跨文獻的思考。

> ⚠️ **草稿不是作業。** AI 可能誤解結果、把結論套到錯誤的文獻、漏掉重要研究或寫出過度概括的句子；查核清單只抓得到部分數字問題。每一句、每個數字、每個引用都要對照原文，改寫成你自己的論述，也請遵守學校、課程或期刊對 AI 使用的規定。

#### 讀懂統計

論文裡的 OR、95% CI、p 值、HR、ITT、效果量、I² 看不懂時，在 PDF 上選那一段，按選取框裡的 **ZotMax：解釋統計**。右側 ZotMax 面板的「統計解釋」分成四塊：

- **這是什麼**：這段出現的每個統計量或術語（英文術語保留），在這段裡的值代表什麼。
- **這段在說什麼**：整段用白話重說一次。
- **臨床上代表什麼**：對照顧病人的意義，效果小或不確定也會直說。
- **要注意的地方**：例如信賴區間跨過 1、區間很寬、統計上顯著但效果很小、多重比較、per-protocol 和 ITT 的差別。

AI 會看你選的文字，加上論文「方法／統計分析」段落的節錄（從全文整理出來；沒有全文時用摘要），以及 AI 文獻筆記裡的研究設計與樣本數。**數字核對**：AI 寫的每個數字都要原樣出現在你選的文字或送出的節錄裡（1·8 和 1.8、.001 和 0.001、全形數字都算同一個數字）；對不上的直接刪掉，換成「［數字已移除］」，並標示「⚠ 這個數字不在原文裡，已移除」。AI 也被要求不自己計算新數字（NNT、百分比變化等），只告訴你怎麼用原文的數字算；唯一例外是說明信賴區間有沒有跨過 0 或 1。

- **再解釋得簡單一點**：再呼叫一次，用更短的句子和臨床例子重講，數字一樣核對。
- **存到筆記**：把這次解釋加進 Obsidian 文獻筆記的「統計筆記」摺疊區塊，附上回到 PDF 那一頁的連結。這個區塊在 ZotMax 管理的區塊之外，是你的：重新同步不會改它，你可以在裡面補自己的理解。文獻筆記要先同步過一次。
- **紀錄**：每篇保留最近 5 次解釋（Zotero 子筆記，標籤 `zotero-bridge-stats`，會跟著 Zotero 同步），最新的展開，舊的摺起來。這份子筆記不會當成你的筆記同步，也不會送給 AI。
- **費用**：一段選取通常是一次很短的呼叫，預設不跳確認視窗，預估費用直接顯示在「AI 解釋中…」旁邊；超過門檻（預設 US$0.05）才先問你。設定 → AI → 讀懂統計 可以改成每次都問或不問。

<summary>AI 文獻筆記：研讀欄位、可引用句查證、重新產生、掃描版 PDF</summary>

- **研讀欄位存在哪裡**：Zotero AI 子筆記最後的「📋 結構化資料」JSON 區塊。之後不呼叫 AI 的同步也沿用；你可以直接在 Zotero 改那段 JSON。它不會出現在 Obsidian／Notion 的內文。
- **可引用句查證的規則**：忽略大小寫、彎引號、PDF 換行斷字、中文字間空白；省略號 … 前後分段比對；九成以上的字依序相符就算找到。找不到標「⚠️ 未在全文中找到」；沒有全文標「⚠️ 無全文可查證」。進度視窗會顯示查證結果。
- **AI 標重點**：存在結構化資料裡；和你的劃線重疊時以你的為準；文獻筆記另列「AI 標的重點（僅供參考）」，排在你的劃線與評讀之後；對不上全文的直接刪掉，進度視窗會說刪了幾句。
- **重新產生**：會覆寫 AI 子筆記（標籤 `zotero-bridge-ai`）；舊內容另存成子筆記（標籤 `zotero-bridge-ai-history`），只留在 Zotero，不同步、不送給 AI，不需要時可以刪。
- **右側面板**：ZotMax 面板的「重點」顯示一句話摘要、研究設計與主要發現，完整的 AI 筆記折在下面；整個面板收合時標題列顯示摘要。還沒有 AI 筆記時可以直接按「產生 AI 筆記」。

**掃描版 PDF（沒有文字層）**：外掛先判斷每篇的全文狀況，寫進 frontmatter `full_text` 與 Notion 的 `全文狀態`（由外掛管理）：

| 值 | 意思 | 判斷方式 |
|---|---|---|
| `ok` | 有全文 | PDF（或 EPUB、網頁快照）有文字層 |
| `partial` | 部分掃描 | 平均每頁不到 600 個字元（不含空白） |
| `none` | 掃描版 | 平均每頁不到 100 個字元：沒有文字，或只有下載浮水印 |
| `no_pdf` | 沒有 PDF | 沒有附件，或檔案不在這台電腦上 |

- 頁數取自 Zotero 的全文索引或 PDF 工具；讀不到頁數時，少於 20 字元才判為 `none`。多個附件取最好的那個。
- 產生 AI 筆記時，進度視窗在該篇顯示 ⚠️，例如「掃描版 PDF（沒有文字層），AI 只讀了摘要與劃線」。
- **掃描版 PDF 直接傳給 AI 讀**（設定 → AI → AI 服務 → AI 文獻筆記，預設開啟）：`none`／`partial` 的 PDF 把檔案本身傳給 AI 看每一頁（Claude；OpenAI 官方 API 也支援，自訂 API base URL 時不傳）。上限 20 MB、100 頁，可在 Config Editor 改 `extensions.zotero-bridge.llm.pdfMaxMB`、`llm.pdfMaxPages`；超過或 API 拒絕時改用摘要與劃線。**比較耗 token**：每頁都當影像計費，費用預估可能**低估**。AI 讀的是影像，所以摘要與劃線裡也找不到的可引用句標「⚠️ 無全文可查證」。
- **比較省錢的做法是讓 PDF 有文字層**：用 [OCRmyPDF](https://ocrmypdf.readthedocs.io/)（`ocrmypdf --language eng+chi_tra 掃描.pdf 輸出.pdf`）或 Adobe Acrobat 的「辨識文字」處理後放回 Zotero，或重新下載有文字的版本；重新索引後再「重新產生 AI 筆記」。
- **沒有東西可讀就不呼叫 AI**：沒有全文、沒有傳 PDF、沒有摘要、也沒有劃線或筆記時略過 AI 筆記，避免 AI 只憑標題編內容；Notion／Obsidian 照常同步。
- 「全文最多送出字元數」設成 0 時不送全文也不傳 PDF。

**外掛怎麼把關**
- 優先用各篇的 AI 筆記（含研究設計、樣本數、證據等級、評讀）；沒有的改用摘要與劃線。

- 草稿裡的數字（樣本數、百分比、p 值、效應量）和所引文獻的 AI 筆記、結構化資料、摘要與劃線比對，找不到的列在查核清單，內文不改。比對的不是 PDF 全文，所以「沒列出」不等於「正確」。
- 重新產生只覆寫自動區塊；要修改草稿，請複製到標記外或你的論文檔再改。

<summary>實證健康照護報告草稿：對話框、產出、哪些是外掛做的、哪些是 AI 寫的</summary>

1. 分類右鍵（或選取要評讀的文獻）→ **產生實證健康照護報告草稿（AI）**。分類有篩選標籤時只用**全文納入**的研究。A 類文章重在少而精、逐篇深度評讀，撰寫指引的理想組合是 1 篇系統性回顧 + 2 篇 RCT。
2. 對話框（記在這個分類，下次自動帶出）：
   - **案例情境**：年齡、診斷、治療狀況，以及病人實際說的話（用「」）。AI 只引用這裡的原話，不會自己編；沒有的地方標〔待補〕。
   - **PICO**：各篇一致時自動帶入；不一致的欄位留空並列出各篇的寫法。
   - **問題類型**：治療／預後／診斷／病因（傷害）／質性，決定用 Oxford CEBM 2011 的哪一欄。
   - **文獻搜尋**：有篩選標籤時由 PRISMA 計數帶入；有 PubMed 追蹤匯入這個分類時帶入它的檢索式；都沒有時依 PICO 組一個並標明「尚未實際檢索」。限制條件與搜尋日期請自己填。
3. 確認預估費用後送出（一次 API 呼叫）。
4. 產出 `Zotero/Drafts/實證報告-<分類>.md`：題目、中英文摘要、前言、方法（表一 PICO 關鍵字表；文獻搜尋與圖一 PRISMA 流程圖；表二證據表與逐篇評讀）、證據綜整、臨床應用、結論與建議、參考文獻，文末是「⚠️ 查核清單」「📋 評分項目自我檢核」與 Pandoc 指令（`--lua-filter zotero-bridge-ebhc.lua`；流程圖在 Word 裡換成「請插入圖一」，請從 Obsidian 匯出圖片後貼上）。

- **外掛依你的資料產生、不經 AI**：表一（同義字與 MeSH 欄留〔待補〕）、搜尋策略、PRISMA 計數與流程圖、表二證據表、參考文獻（中文文獻用中文 APA）。
- **AI 撰寫敘述**：只能用 [S#] 代號；逐篇評讀沿用 AI 筆記（或你核對過的評讀表）的逐題結果，不能自己增刪題目或改答案；資料沒有的數字、原話一律〔待補〕。
- **查核清單**：數字比對，並檢查缺少的章節、沒有逐篇評讀的文獻、PICO 缺項、資料庫是否含 Cochrane Library 與 PubMed、是否有 PRISMA 圖、評讀工具是否為指引要求的 CASP、問題類型與 CEBM 欄位、摘要與全文字數（粗估）、評讀者分工等。
- **評分項目自我檢核**：把撰寫指引的配分（題目 5、摘要 13、前言 5、PICO 10、文獻搜尋 20、文獻評讀 25、結論與建議 12、參考文獻 5）對應到草稿段落。**這不是評分**，也不代表能通過審查。

結構與配分整理自「A 類實證健康照護綜整文章發表準則暨撰寫指引（1141020 修訂版）」與已發表範例的寫作指南；準則、評讀工具版本與評分表會更新，**請以台灣護理學會最新公告為準**。搜尋策略與篇數要和你實際的搜尋紀錄一致。

#### 在 Obsidian 寫論文並用 Pandoc 產生 APA Word

<details>
<summary>匯出參考文獻檔、citekey 從哪裡來、Pandoc 指令、中文文獻的限制</summary>

**1. 匯出參考文獻檔**

| 方式 | 產出 |
|---|---|
| ZotMax 按鈕或快速指令 → **匯出參考文獻到 Obsidian** | `Zotero/references.json`：我的文獻庫和群組文獻庫的所有文獻 |
| 分類右鍵 → **ZotMax ▸ 匯出目前分類的參考文獻** | `Zotero/references-<分類>.json`（含子分類），citekey 和主檔相同 |
| 設定 → 同步 → 參考文獻檔 →「同步時自動更新參考文獻檔」（預設關閉） | 每次同步後更新 `references.json`，內容沒變不寫入 |

- 主檔包含整個文獻庫：Pandoc 只列內文真的有引用的，還沒建筆記的文獻也能直接引用。
- 要 BibTeX（例如寫 LaTeX）就勾「同時匯出 references.bib」，用 Zotero 內建匯出器，citekey 一樣。

**citekey 從哪裡來**（和文獻筆記 frontmatter 的 `citekey` 相同）：
1. Zotero 10 的 **Citation Key** 欄位
2. Better BibTeX 的 citekey（有安裝時）
3. 都沒有時自動產生：第一作者姓氏 + 年份 + 標題第一個字（略過 the、a、of 等），例如 `chen2024effects`；中文取標題前四個字，例如 `陳2023護理人員`。撞名時較晚加入的加 a、b、c。

自動產生的 citekey 記在 `Zotero/.zotero-bridge-citekeys.json`，之後不變；文獻刪除後也不會轉給別篇。修改第一作者、年份或標題第一個字時會換成新的。論文要長期引用的文獻，建議直接在 Zotero 填 Citation Key。

**2. 安裝 Pandoc 與 APA 7 樣式**：安裝 [Pandoc](https://pandoc.org/installing.html)（2.11 以上），從官方 CSL 樣式庫下載 [`apa.csl`](https://github.com/citation-style-language/styles/blob/master/apa.csl)（[直接下載](https://raw.githubusercontent.com/citation-style-language/styles/master/apa.csl)）放在 vault 根目錄。

**3. 在 Obsidian 引用**

| 寫法 | APA 7 輸出 |
|---|---|
| `[@chen2024effects]` | (Chen, 2024) |
| `[@chen2024effects, p. 5]` | (Chen, 2024, p. 5) |
| `@chen2024effects` | Chen (2024)：敘述式引用 |
| `[@chen2024effects; @lee2021sleep]` | (Chen, 2024; Lee, 2021) |

Pandoc 會把參考文獻列表放在文件最後，在論文最後寫一個 `# 參考文獻` 標題即可。

**4. 產生 Word 檔**（在 vault 根目錄執行）：

```bash
pandoc 論文.md --citeproc --bibliography Zotero/references.json --csl apa.csl -o 論文.docx
```

- 套用學校的字型、行距與邊界：準備一份格式正確的 Word 檔，加上 `--reference-doc 範本.docx`。
- `[[內部連結]]` Pandoc 不會轉換，交稿用的檔案請改成一般文字。

**5.（選用）邊寫邊預覽**：安裝社群外掛 **Pandoc Reference List**，填入 `Zotero/references.json` 的完整路徑與 `apa.csl`，側欄會列出這份筆記引用的文獻，方便檢查 citekey 有沒有打錯。

**中文文獻在 Pandoc 的限制**：`references.json` 裡中文姓名寫成完整姓名（`"literal": "陳美玲"`），中文文獻加 `"language": "zh-TW"`，所以內文是 `(陳美玲 et al., 2023)`、參考文獻 `陳美玲, 林小華, & 歐陽志明. (2023). …`：姓名對了，但標點與用語仍是英文規則，中文文獻也排在英文後面。目前沒有 Pandoc 能用的中文 APA 樣式（[Zotero 中文社群的樣式](https://github.com/zotero-chinese/styles)用 CSL-M，Pandoc 的 citeproc 不支援，見 [citeproc 更新紀錄](https://github.com/jgm/citeproc/blob/master/CHANGELOG.md)），所以外掛沒有附 CSL 檔。交稿前建議：英文文獻用 Pandoc 的結果；中文文獻從文獻筆記的「APA 7」或比較表的參考文獻複製（Obsidian 閱讀模式複製會保留斜體），放在最前面，並把內文的 `et al.` 改成「等」、`&` 改成「、」。

</details>

## 常見問題與疑難排解

**沒有 API key 可以用嗎？** 可以。同步、閱讀狀態、評讀表、篩選與 PRISMA、儀表板、搜尋連結都不需要 AI。沒有 key 時按一般同步，外掛會提示「AI 筆記需要 API key」；請改用「同步但不呼叫 AI」，或到「功能」關掉「AI 文獻筆記」。

**我有 ChatGPT Plus／Claude Pro，可以直接用嗎？** 不行。這裡要的是 API key，API 另外計費。

**重新同步會蓋掉我寫的東西嗎？** 不會。外掛只改自己的區塊（見[收集與同步](#收集與同步)）。直接改 AI 子筆記也沒問題，下次同步會沿用你改過的內容。

**選單裡找不到某個功能？** 先到 設定 → ZotMax → 功能 看開關是不是關著（研究生引導有些預設關閉）。找重複、PRISMA、評讀總表、引文追蹤納入研究要先在左側選一個分類；其他功能要先選文獻。

**AI 筆記看起來只讀了摘要？** 多半是掃描版 PDF 或沒有 PDF，進度視窗會顯示 ⚠️，frontmatter 的 `full_text` 也會標出。先用 OCR 讓 PDF 有文字層，再「重新產生 AI 筆記」。

**同步到一半想停，或 Zotero 當掉了？** 工具 → **停止 ZotMax 同步**；之後 **繼續未完成的 ZotMax 同步**，失敗的會一起重試。

**同步到 Notion 很慢？** Notion API 大約每秒 3 次請求。圖片劃線每次都要重新上傳，Notion 全文子頁面每篇也要 5–10 次請求，不需要的話可以關掉。

**Notion 已經有一個「狀態」類型的 `Status` 欄位？** 外掛不會動它。把它改名後再按「測試連線並補齊資料庫欄位」，外掛會建立單選的閱讀狀態欄位。

**可以和 Notero 一起用嗎？** 可以並存，但**不要讓兩者寫入同一個 Notion 資料庫**，不然同一篇會有兩頁。建議改用本外掛的分流規則。

**Zotero 刪掉的文獻，筆記會怎樣？** Notion 頁面移到 Notion 垃圾桶；Obsidian 筆記不會刪，只把 `status` 改成「已刪除」。

**出錯了去哪裡看？** 進度視窗會列出每一篇的結果；詳細記錄在 Zotero 的 說明 → 除錯輸出記錄。仍然有問題，請到 [GitHub Issues](https://github.com/bobyu89/zotero-bridge/issues) 回報。

**Zotero 出新的大版本後外掛被停用？** 外掛宣告支援到 Zotero 10.x，依 Zotero 規定不能預先宣告未來版本。Zotero 11 推出時會先停用外掛，確認相容後會自動恢復，不用重新安裝。

## 隱私與費用

**API key 存在哪裡**：AI 的 API key、Notion token 和 NCBI API key 都存在 Zotero 的密碼管理員（和 Zotero 同步帳號的 key 同一套機制；有作業系統鑰匙圈時會再加密），不會寫進設定檔 `prefs.js`。舊版存在 `prefs.js` 的金鑰會在啟動時自動搬過去並刪除。

**什麼時候送什麼給 AI**：只有你打開對應開關、而且有 API key 時才會送。

| 什麼時候 | 送出什麼 |
|---|---|
| 同步時產生 AI 筆記（沒有 AI 筆記的文獻）、重新產生 AI 筆記 | 書目、摘要、全文（見下）、你的劃線評註和 Zotero 子筆記；掃描版 PDF 的檔案本身（預設開啟）；圖片劃線截圖（預設關閉，只限 Claude） |
| 文獻比較表、文獻探討草稿、實證報告草稿、概念卡片 AI 綜整 | 各篇的 AI 筆記與結構化資料（沒有的用摘要與劃線）；草稿另外送你在對話框填的研究問題、大綱或案例情境 |
| AI 主題分類 | 標題、摘要、一句話摘要和你的主題清單 |
| 評讀陪練（按「對照 AI」） | 這篇的標題、年份、全文（沒有全文時用摘要）和評讀工具的題目；**不送你的答案和評析** |
| 讀懂統計 | 你在 PDF 選的文字、論文方法／統計分析段落的節錄（沒有全文時用摘要）、AI 筆記的研究設計與樣本數 |
| 進度報告的 AI 摘要（預設不勾） | 報告裡列出的資料 |

**不會呼叫 AI 的**：自動同步、PubMed 自動檢查、研究儀表板、概念卡片（不含 AI 綜整）、全文筆記、篩選與 PRISMA、評讀表（不含評讀陪練）、進度報告本身。評讀表子筆記和舊版 AI 筆記不會送給 AI。

**其他連網**：Notion（同步時）；NCBI（PubMed 追蹤與 MeSH 建議，附你填的 email 與 NCBI API key）；OpenAlex（引文追蹤，附你填的 email）。搜尋連結只是在瀏覽器開資料庫的網址，裡面只有檢索詞。網站上的快速搜尋與評讀表不會把資料送到任何伺服器。

**費用**：AI 費用由你自己的帳號支付。
- 一次替超過 5 篇產生 AI 筆記前會先確認；有用量紀錄時附上預估費用（依過去的平均用量估算，掃描版 PDF 可能低估）。文獻比較表、草稿、AI 主題分類、評讀陪練也都先確認。
- **用量**：設定 → AI → 本月 AI 用量 顯示呼叫次數、tokens、估計費用（美元），可重設；每次 AI 執行後進度視窗也有一行摘要，研究儀表板列出近三個月。估計用的價格表可以在同一區修改；OpenAI 沒有內建價格，只顯示 tokens。估計值僅供參考，以服務商帳單為準。
- **全文先刪參考文獻**：「全文筆記」開著時，送給 AI 的全文是整理好的 Markdown，並先刪掉 References、Acknowledgements、Funding、Conflict of interest（設定 → 整理 → 全文筆記 可關）。同步完成時進度視窗會顯示「全文整理成 Markdown 後送給 AI：N 字（原本 M 字，省下 X%）」。
- **全文最多送出字元數**：預設 150,000，在刪減之後才截斷；設成 0 只送摘要與註記，最省。
- **提示快取**（Claude，自動）：每篇請求開頭相同的筆記模板會被快取，連續產生多篇時後面幾篇的開頭便宜很多。
- **批次 API**（Claude，「批次 API」開關）：大量產生 AI 筆記時約半價，但最久等 24 小時。

<details>
<summary>提示快取與批次 API 的細節</summary>

**提示快取（prompt caching）**
- 每篇筆記的請求開頭都一樣：筆記模板（含嚴格評讀規則）＋結構化資料的說明，約數千 tokens。外掛把這段標成可快取，每篇的書目、摘要、全文、註記、PDF、圖片都放在快取點之後，所以連續產生時後面幾篇的開頭以快取讀取計費（遠低於一般輸入）；第一次寫入快取要多付 25%（5 分鐘快取）。
- 快取約 5 分鐘內有效（每次讀取重新計時），逐篇產生時通常一路命中。文獻比較表、草稿等其他 Claude 呼叫也快取各自的模板。
- 開頭太短不會被快取（不會出錯也不多收費）：最短長度依模型而定，約 512–4096 tokens。內建模板夠長；自訂一個很短的模板時可能就不會快取。
- 「本月 AI 用量」顯示快取讀取／寫入的 tokens 與「提示快取：省下約 US$…」。
- OpenAI 也有自動的提示快取，外掛不需設定。

**批次 API（Message Batches）**
- 開啟後，手動同步時需要產生 AI 筆記的文獻達門檻（預設 10 篇，設定 → AI → AI 服務 → 批次 API 可改），確認視窗同時列出一般模式與批次 API 的預估費用，讓你選「批次 API（約半價）」「一般模式（立即產生）」或取消。
- 選批次：每篇請求（和一般模式內容相同，含掃描版 PDF 與圖片劃線）打包送出，**所有 tokens 都是一般價格的 50%**。不需要 AI 的文獻照常立即同步。
- 通常 1 小時內完成，最長 24 小時。外掛每 2–5 分鐘檢查一次；**Zotero 關閉也沒關係**，下次開啟會繼續檢查。完成後寫入 AI 筆記、記入用量，再自動「同步但不呼叫 AI」並通知你。
- 失敗的（請求錯誤、超過 24 小時、取消、模型拒絕處理）加入接續清單：工具 → **繼續未完成的 ZotMax 同步** 用一般模式重試。
- 工具 → **檢查 AI 批次進度**（已完成幾篇、等了多久、最晚何時結束）；工具 → **取消 AI 批次**（已完成的仍會寫入，尚未處理的不收費）。
- 批次請求用 1 小時的快取，寫入費為一般輸入的 2 倍（再打五折）；批次中的快取命中不保證。
- **只支援 Claude**；選 OpenAI 時一律用一般模式。「本月 AI 用量」會分開列出「批次 API：N 次呼叫，比一般模式省下約 US$…」。

</details>

## 給開發者

```bash
npm install
npm test         # 單元測試 + 模擬 Zotero 環境的整合測試
npm run build    # 產生 dist/zotero-bridge-<version>.xpi，並更新 updates.json
```

- **名稱**：ZotMax 舊名 Zotero Bridge（0.10 以前）。改的只是顯示名稱：外掛 ID `zotero-bridge@bobyu89.github.io`、偏好設定 `extensions.zotero-bridge.*`、儲存 API key 的登入資料、`chrome://zotero-bridge/`、Fluent 檔名與訊息 ID、repo 與網址、`.xpi` 檔名都沒變，所以舊版會自動更新並保留設定；舊版寫的筆記標記（例如 Notion 頁面上「Zotero Bridge｜…」的區塊）仍會被認得並就地更新。
- **產品與設計**：[PRODUCT.md](PRODUCT.md)（使用者、定位、原則）、[DESIGN.md](DESIGN.md)（設定頁與網站的視覺規範）。功能開關的目錄在 `content/features.js`，字串在 `locale/*/zotero-bridge.ftl`，預設值在 `prefs.js`。
- **發布新版本**：改 `manifest.json` 的 `version` → `npm run build`（`.xpi` 與 `updates.json` 都要提交；`test/release.test.cjs` 會檢查兩者一致）→ 推送到 `main`，GitHub Actions（`release.yml`）建立 Release，Zotero 自動更新。已發布版本在 `updates.json` 的項目不可更動。
- **Zotero 出新的大版本**：在新版 beta 上安裝外掛，照[安裝精靈](https://bobyu89.github.io/zotero-bridge/)第 7 步試跑一篇文獻、一次文獻比較表；沒問題就執行 `npm run compat -- 11.*`，把 `manifest.json` 與 `updates.json` 推到 `main`，已安裝的使用者會自動恢復啟用，不用發新版。有問題就修正後發新版。依 Zotero 規定，相容版本只能宣告到目前已測試的大版本。

### 真實 Zotero 測試（e2e）

`npm test` 用模擬的 Zotero；`.github/workflows/e2e.yml` 則把建置好的 `.xpi` 裝進**真正的 Zotero 10**（Linux 版、當下最新的正式版）跑一次。每次 push、PR 自動執行，也可以在 GitHub → Actions → **e2e** → **Run workflow** 手動跑。不連 Notion 或任何 AI 服務。

<details>
<summary>e2e 怎麼跑、檢查哪些項目</summary>

`test/e2e/run.sh` 建立全新的 Zotero 設定檔，把外掛和測試用的小外掛（`test/e2e/harness/`）放進去，在 Xvfb 下啟動（另開一個已解鎖的 gnome-keyring）。Zotero 啟動兩次：先**不裝外掛**記下 Zotero 本身的主控台錯誤（`baseline.json`），再裝外掛執行檢查，結果寫進 `results.json`。結果表格在該次 Actions 的摘要；失敗時另外上傳 `results.json`、`zotero.log` 和測試用的 vault。

- 外掛已啟用、所有模組都載入；啟動時沒有外掛的錯誤，也沒有「不裝外掛時不會出現」的錯誤
- 右鍵（各一個 ZotMax 子選單）／工具選單、設定頁、條目窗格區塊都有註冊；快速指令視窗打得開、找「分類」第一個是文獻自動分類、Esc 關閉、快捷鍵有效；所有 Fluent 字串在 en-US 與 zh-TW 都找得到
- API key 經由真正的密碼管理員存取並有作業系統鑰匙圈加密；舊版設定的搬移
- 在真的文獻庫建立條目（中文作者、子筆記、標籤、分類）與 PDF 附件（有文字層的與純圖片的），由 Zotero 的 PDF worker 判斷 `ok`／`none`／`no_pdf`
- 同步到 Obsidian（不呼叫 AI）：筆記、frontmatter、`.base` 檔、中文 APA 與 Zotero citeproc 的英文 APA
- 閱讀狀態寫回 Zotero 標籤；`references.json` 與 `references.bib`
- 篩選決定寫到標籤，產生 PRISMA 筆記與證據表 CSV
- 自動同步；AI 筆記（只把外掛內的 `fetch` 換成假的 Claude 回應）
- 文獻自動分類（只用規則與研究設計推測）：建立子分類、不重複建立、復原後清乾淨、原本的分類不變；確認視窗按「取消」不寫入
- 條目窗格顯示 AI 筆記；設定頁能開啟、值與已存的 token 正確，關閉後新輸入的 key 有存下
- 工具列按鈕的位置、名稱、圖示、方向鍵；兩種模式下選單依開關顯示；關掉「工具列按鈕」即時隱藏
- 停用再啟用外掛：選單、區塊、FTL、工具列按鈕都清掉再註冊回來

Zotero 10.0.6 每註冊一次外掛的語系檔就會在主控台記一筆 `uncaught exception: undefined`（不裝外掛時一樣會發生，由 baseline 驗證），不算外掛的錯誤。

</details>

<details>
<summary>外部服務連線檢查（link-check）</summary>

開發環境連不到 PubMed、OpenAlex 和各資料庫，所以 `.github/workflows/link-check.yml` 在 GitHub Actions 上實際連線（每週一自動執行；改了 `content/search-links.js`、`pubmed-watch.js`、`citation-chase.js`、`site/search.html` 也會跑；可在 Actions → **link-check** → **Run workflow** 手動執行）。

- `test/live/check-links.mjs` 用外掛與網頁的資料庫清單組出每個搜尋網址，以 `fall prevention older adults`（中文資料庫用 `跌倒 預防`）實際開啟：一般 HTTP 連線加上無頭 Chromium，判斷是結果頁、首頁、登入頁、被擋或壞掉。不確定的會試其他網址寫法，開首頁的會在網站搜尋框實際輸入。
- NCBI E-utilities：用外掛自己的函式組網址、解析回應，確認用到的欄位都還在。
- OpenAlex：引文追蹤用到的每個參數，最後用 `chase()` 對一篇常被引用的護理研究（Aiken et al., 2002, JAMA）實際跑一次。
- 結果在該次執行的摘要與 `link-check-report` 附件。只有明確壞掉（404、網址錯誤、NCBI／OpenAlex 欄位不符）才算失敗；擋雲端主機的網站標成「被擋」，不算失敗。

</details>
